## 三、模块拆解与实现

### 模块 1：独立站（WordPress + Astro）

**职责**：公司资质展示 + 产品目录 + 产品详情 + 联系方式 + 询盘表单

**技术方案**：

```
WordPress (docker-wordpress)  →  主站（公司介绍、联系、博客）
  ├── 产品目录页（自定义文章类型：Products）
  ├── 产品详情页（含规格参数、PDF下载）
  ├── 公司资质页（ISO/CE/PVOC 证书展示）
  └── 询盘表单（WPForms → Webhook → n8n → CRM）

AstroWind (astrowind)  →  产品详情静态页（SEO 友好）
  └── 从 Obsidian 产品 Markdown 自动生成
```

**产品数据流**：

```
Obsidian 产品 Markdown
    ↓ (n8n Webhook 触发)
WordPress REST API（创建/更新产品文章）
    ↓
独立站产品页自动更新
```

**关键插件**：
- WP REST API（核心自带）
- Advanced Custom Fields（产品规格字段）
- WPForms（询盘表单 → Webhook）
- Yoast SEO（SEO 优化）

**Astro 的角色**：用 Astro 生成产品详情的静态 HTML 版本，SEO 极致优化，作为独立站的"产品详情"子目录，或单独域名。WordPress 做动态内容（博客/新闻），Astro 做静态产品页。

### 模块 2：社媒矩阵（Postiz）

**职责**：Facebook 多账号排期发布 + 数据回收

**已有基础**：Postiz docker-compose 已配好 Facebook App ID/Secret、LinkedIn、Temporal 调度

**矩阵架构**：

```

  ├── 账号 1：公司主页（品牌窗口）
  ├── 账号 2：老板个人号（行业专家）
  ├── 账号 3：业务员号 A（产品顾问）
  ├── 账号 4：业务员号 B（产品顾问）
```

**内容自动排期流**：

```

    ↓ (n8n 定时读取)
DeepSeek AI（生成/润色英文帖文）
    ↓
Postiz API（排期发布到各账号）
    ↓
发布数据回收（曝光/互动/点击）
    ↓
n8n → CRM（线索归因）
```

**Postiz 已支持的平台**：Facebook、LinkedIn、X/Twitter、Instagram、TikTok、YouTube、Pinterest、Threads、Reddit、Discord

### 模块 3：WhatsApp 聊单系统

**职责**：客户沟通 + 聊天记录同步到 CRM

**方案选型**：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **WhatsApp Business API（官方）** | 稳定、合规、支持群发 | 需要 BSP 服务商（如 Twilio/360dialog），有费用 |
| **WhatsApp Web 多开 + 自动化** | 免费 | 非官方，有封号风险 |
| **n8n WhatsApp 节点** | 集成方便 | 需要官方 API 或第三方桥接 |

**推荐方案**：WhatsApp Business API + n8n 集成

```
WhatsApp Business API (360dialog/Twilio)
    ↓ Webhook
n8n (:5678)
    ├── 解析消息内容
    ├── AI 分类（询价/报价/售后/闲聊）
    ├── 同步聊天记录到 CRM
    ├── 自动回复（常见问题）
    └── 通知业务员（紧急询盘）
```

**CRM 中的 WhatsApp 数据模型扩展**：

```
Contact
  ├── whatsapp_phone: String
  ├── whatsapp_chat_history: Json[]
  │     ├── { from: "customer", message: "...", timestamp: "..." }
  │     ├── { from: "agent", message: "...", timestamp: "..." }
  │     └── ...
  ├── lead_score: Int
  └── ai_classification: String  // "inquiry" | "negotiation" | "after_sales"
```

## 四、n8n 工作流设计（核心胶水）

### Workflow 1: 产品目录同步

```
触发器：Obsidian 文件变更（轮询或 Webhook）
    ↓
读取 .md 文件
    ↓
解析 YAML Frontmatter
    ↓
DeepSeek AI：生成 SEO 标题和描述
    ↓
HTTP Request：WordPress REST API 创建/更新文章
    ↓
记录日志
```

### Workflow 2: 社媒内容自动排期

```
触发器：每周一 9:00 定时
    ↓
读取 Obsidian /Content/ 目录
    ↓
DeepSeek AI：为每个产品生成 3 条 Facebook 帖文
    ↓
HTTP Request：Postiz API 创建排期帖文
    ↓
通知业务员审核确认
```

### Workflow 3: WhatsApp 聊天同步

```
触发器：WhatsApp Webhook（新消息）
    ↓
解析消息（发送者/内容/时间）
    ↓
DeepSeek AI：分类消息类型
    ↓
HTTP Request：CRM API 创建/更新联系人
    ↓
if（询盘意向）→ 通知业务员 + 自动回复模板
```

### Workflow 4: 客户背调自动化

```
触发器：CRM 新联系人（询盘来源）
    ↓
获取联系人信息（公司名/域名）
    ↓
DeepSeek AI + Web Search：背调查询
    ↓
HTTP Request：CRM API 更新联系人背调字段
    ↓
if（风险客户）→ 标记 + 通知
```

### Workflow 5: 独立站询盘同步

```
触发器：WordPress 表单提交（Webhook）
    ↓
解析表单数据（姓名/公司/产品/数量/邮箱）
    ↓
DeepSeek AI：询盘评分
    ↓
HTTP Request：CRM API 创建联系人 + 询盘记录
    ↓
通知业务员（WhatsApp/邮件）
```

## 七、Obsidian → 独立站同步实现

### 方案 A：n8n 轮询（简单可靠）

```javascript
// n8n workflow: 轮询 Obsidian 产品目录
// 每 30 分钟检查一次文件变更

1. Cron Trigger → 每 30 分钟
2. Read Binary File → 读取 Obsidian Vault/Products/ 下所有 .md 文件
3. Hash 比对 → 与上次读取的 hash 比较
4. IF hash 不同 → 执行同步
5. Parse Markdown → 提取 frontmatter + body
6. HTTP Request → WordPress REST API
   POST /wp-json/wp/v2/posts
   {
     "title": "M10x30 Hex Bolt Grade 8.8",
     "content": "<html product content>",
     "status": "publish",
     "categories": [产品分类ID],
     "acf": { 产品规格字段 }
   }
7. Log → 记录同步结果
```

### 方案 B：Obsidian URI + n8n Webhook（实时）

```javascript
// Obsidian 配置 Advanced URI 插件
// 保存文件时自动触发 n8n Webhook

1. Obsidian Advanced URI → 保存时调用 Webhook
2. n8n Webhook Trigger → 接收文件内容
3. Parse Markdown → 提取数据
4. WordPress REST API → 更新产品页
```

### 方案 C：Git 同步（版本控制）

```
Obsidian Vault (Git repo)
    ↓ (保存时自动 commit + push)
n8n Git Trigger → 检测新 commit
    ↓
读取变更的 .md 文件
    ↓
WordPress REST API → 更新
```
